# 🚀 시스템 아키텍처 및 성능 개선 계획 (IMPROVEMENT PLAN)

> **작성일**: 2026-06-21

본 문서는 최근 수행된 코드베이스 정밀 검토 및 핵심 버그 픽스 완료(Critical & Significant 대부분 해결) 이후, 시스템의 구조적 한계를 극복하고 프로덕션 레벨의 안정성을 확보하기 위한 중장기 개선 계획입니다.

## 1. 데이터 파이프라인 및 병목 해소

### 1.1 펀더멘탈 데이터 수집 및 캐싱 (이슈 I9)
- **현재 상황**: 매 파이프라인 실행 시마다 야후 파이낸스(`yfinance`)를 통해 3,000여 개 종목의 펀더멘탈 데이터를 재수집하여 네트워크 병목 및 Rate Limit 문제 발생.
- **개선 계획**:
  - `MarketIndicatorStorage` 내에 펀더멘탈 전용 캐시 테이블 고도화.
  - 일 단위(Daily)가 아닌 분기 단위(Quarterly) 업데이트 로직을 구현하여 빈번한 네트워크 요청 제거.
  - 비동기 IO (`aiohttp` + `asyncio`)를 전면 도입하여 수집 속도 개선 (기존 ThreadPoolExecutor 대체).

### 1.2 "펀더멘탈 데이터 누락(0.0) 편향" 해결 (이슈 S4)
- **현재 상황**: 재무 데이터가 없는 종목은 0.0으로 일괄 채워짐(`fillna(0.0)`). 이는 실제 0(예: 배당수익률 0%)과 데이터 누락을 모델이 구분하지 못하게 함.
- **개선 계획**:
  - `has_fundamental` (0 또는 1) 바이너리 피처를 추가하여 모델에 맥락 제공.
  - XGBoost 및 LightGBM이 기본적으로 지원하는 `NaN` 최적화 분기(Sparsity-aware Split Finding)를 적극 활용하도록, 결측치를 0.0 대신 `np.nan`으로 유지.

### 1.3 데이터베이스 동시성 문제 (이슈 I5, S6 후속)
- **현재 상황**: SQLite의 WAL 모드와 Python `threading.Lock`을 통해 `database is locked` 에러를 일차적으로 방어함.
- **개선 계획**:
  - 향후 트래픽 증가 및 다중 에이전트 환경 확장을 고려하여 PostgreSQL로의 마이그레이션 추진.
  - SQLAlchemy 또는 asyncpg를 도입하여 커넥션 풀링(Connection Pooling) 구성.

## 2. 테스트 커버리지 및 안정성 확보

### 2.1 통합 테스트 스위트 보강 (이슈 I1, I2, I4)
- **현재 커버리지**: 약 35~40%
- **목표 커버리지**: 60% 이상 확보
- **개선 계획**:
  - `config.py`의 다양한 설정 조합에 대한 유닛 테스트 추가.
  - `backtest.py` 전용 테스트 작성 (Mock 데이터를 활용한 가상 매매 검증).
  - SQLite 병렬 쓰기 상황을 재현하는 스트레스 테스트 벤치마크 작성 (이슈 I3).

### 2.2 CI/CD 파이프라인 도입 (이슈 I11, I12)
- **개선 계획**:
  - GitHub Actions 기반의 자동화 워크플로우 구성.
  - PR 생성 시 `pytest`, `ruff`(린팅), `mypy`(정적 타입 검사) 자동 실행.
  - 테스트 완료 후 Coverage Report를 PR 코멘트로 자동 퍼블리시.

## 3. 코드 최적화 및 유지보수성 향상

### 3.1 성능 및 로직 최적화 (이슈 I5, I6)
- **유니버스 조회 병목**: 파이프라인 내부의 O(n²)에 달하는 리스트 조회를 해시맵(Dict/Set) 기반 O(1) 조회로 최적화.
- **오케스트레이터 폴링 루프**: 데몬의 1초 간격 polling(`await asyncio.sleep(1)`)을 30초~60초 간격으로 늘려 불필요한 CPU 점유 축소.

### 3.2 불필요한 의존성 정리 및 리팩토링 (이슈 I7, I8)
- 오케스트레이터 및 파이프라인 코드에서 더 이상 사용하지 않는 패키지(`subprocess`, `ProcessPoolExecutor` 등) 정리.
- `FallbackMetadataDict` 등의 레거시 유틸리티 함수 로직 완전 재작성 혹은 삭제.
- 텔레그램 봇의 예외 처리 강화: 오류 발생 시 전체 traceback이 노출되지 않도록 사용자 친화적 메시지 출력 (이슈 I10).
